# MUSE MVP Implementation Plan

> **For agentic workers:** Use parallel bounded implementation with a final independent review. Checkboxes track deliverables.

**Goal:** A locally runnable, honest humming-to-composition hackathon demo.

**Architecture:** React/Vite client with browser-only Web Audio capture and synthesis. After user steering, a local Node HTTP API owns arrangement, producer requests and restart-persistent SQLite projects. Pure modules expose testable interfaces. The UI never invents microphone results.

**Tech Stack:** React, JavaScript, CSS, Vite, Web Audio API, Node HTTP and SQLite, Node test runner.

**Spec:** User's two MUSE briefs supplied in chat on 2026-11-17.

## Global constraints
- Real microphone analysis and actual synthesised playback.
- Rule-based producer assistant is labeled; no model training or remote API.
- Local Node/SQLite project storage; raw audio stays in the browser; no cloud accounts or uploads.
- Desktop and narrow layouts, keyboard controls, reduced motion, clear errors.

## Review focus
- Permission refusal or missing microphone releases resources and allows retry.
- Silence and noise yield no fabricated notes.
- Pause/resume exclude paused capture time and prevent overlapping playback.
- Settings and producer changes affect the audible arrangement.
- Invalid browser storage recovers without crashing; microphone data remains local.
