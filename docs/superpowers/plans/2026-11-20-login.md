# MUSE login implementation plan

**Goal:** Add real local email/password accounts, persistent sessions and logout while preserving the current music workspace.

**Scope:** The user narrowed the larger community request to login first and selected a local submission build. Registration, login, logout, session restoration and an authenticated current-account endpoint are included. Community, profiles, Google OAuth, email recovery and public deployment belong to later increments.

**Architecture:** Reuse React 19, native Node HTTP and the existing SQLite connection. Add account/session/rate-limit tables without deleting, claiming or migrating existing projects. Keep the studio hook mounted; show account forms in a separate accessible dialog. No external authentication service or new dependency is required.

**Security:** Async salted scrypt password hashing; random 256-bit opaque sessions, only their hashes stored in SQLite; HttpOnly/SameSite cookies; absolute and idle expiry; login rotation and server logout revocation; in-memory CSRF token for logout; strict existing Host/Origin and JSON controls; bounded authentication attempts and concurrent password hashing. Passwords/session tokens never enter localStorage, logs or URLs.

**Files and ownership:** Backend worker creates server/auth.js and tests/auth.test.js. Frontend worker creates useAuth, auth-api, AuthPanel, scoped auth.css and isolated browser checks, integrating App/main without unmounting the studio. Coordinator adds the shared database connection, HTTP dispatch and app-level integration tests.

- [ ] Write meaningful failing backend and frontend regressions.
- [ ] Implement and verify account/session backend.
- [ ] Implement and verify accessible account dialog and session restoration.
- [ ] Integrate with existing HTTP validation and additive database schema.
- [ ] Independently review session/CSRF/rate-limit behavior and UI regressions.
- [ ] Run the complete test suite, production build, HTTP smoke and browser checks where available.

**Compatibility checks:** Original project rows remain intact; guest music stays available; opening/closing account UI preserves captured notes, original recording and arrangement; server outages have a retry path; stale session responses cannot restore a logged-out account; mobile navigation fits; keyboard focus returns to the account trigger.
